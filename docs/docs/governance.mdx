# Governance

<Stamp />

The [Renvor Constitution](https://github.com/renvor-rs/renvor/blob/main/CONSTITUTION.md) —
version 3.0.1, ratified 2026-08-11, last amended 2026-08-19 — is the highest authority in
this project. Where any other document conflicts with it, the constitution wins and the
conflict is a defect in the other document.

It has been amended three times, each through the process the constitution states for itself:
**2.0.0** and **3.0.0** were MAJOR, and **3.0.1** was a PATCH that removed a third-party tool
name from a normative rule without changing what the rule requires. The amendment history is at
the top of `CONSTITUTION.md`.

## Decision records

Substantial architectural decisions are recorded in the repository's `decisions/`
directory. Numbers are four digits, monotonic, and never reused: a rejected or superseded
record keeps its number forever, so references to it never silently retarget.

**A decision with no rejected alternatives was not a decision.** The template requires
alternatives with reasons.

## One maintainer, stated plainly

Renvor currently has a single maintainer, who holds every role: decision authority,
security contact, release approver, and registry owner.

That concentration is the root cause of every active waiver, and it is disclosed rather
than distributed across several titles to look larger than it is.

## Waivers

The constitution permits exceptions only through a **time-bounded written waiver**
recording seven fields: the violated rule, the reason, compensating controls, the owner,
the expiry, the removal plan, and the status.

Rules that make a waiver a waiver rather than a loophole:

- **An absolute expiry date is mandatory.** A condition may accompany it, and the waiver
  ends at whichever arrives first. A condition alone is never enough — a condition that
  never occurs would never expire.
- **Compensating controls must be specific to the gap.** A control that another rule
  already mandates unconditionally compensates for nothing.
- **Security release blockers cannot be waived.**

**Six** waivers are active. Each expires on the date shown **or** when the person it depends
on becomes available — whichever comes first:

| ID | Gap | Phase | Expires |
| --- | --- | --- | --- |
| **W-001** | No second person can approve a pull request | all | 2027-02-11 |
| **W-002** | No independent reviewer exists for decision records | Phase 001 | 2027-02-11 |
| **W-003** | **No independent human requirements and security review of Phase 001 has occurred** *(granted 2026-08-15)* | Phase 001 | 2027-02-11 |
| **W-004** | **No independent reviewer exists for ADR-0007**, the Phase 002 custom-primitives decision record *(granted 2026-08-16)* | Phase 002 | 2027-02-16 |
| **W-005** | **No independent human requirements and security review of Phase 002 has occurred** *(granted 2026-08-16)* | Phase 002 | 2027-02-16 |
| **W-006** | **No independent reviewer exists for ADR-0009**, the record removing `image-size` from this site *(granted 2026-08-17)* | Phase 002 | 2027-02-11 |

Under W-002, decision-record review is a **structured self-review**, and it is never
described as independent. **All six** Phase 001 decision records — ADR-0001 through
ADR-0006 — are `accepted` under W-002's compensating controls, each with a recorded
reviewer and review date. ADR-0006 was the last, accepted on 2026-08-15 once **T106**,
the maintainer ruling on the shared server's absent backups, was closed.

**None of those reviews is independent**, and none may be described as such. A separate
waiver, **W-003**, covers the same gap at the phase level: Phase 001 has had **no
independent human requirements and security review**, and it must receive one before any
public release.

Phase 002 repeats the pattern rather than borrowing Phase 001's waivers, because a waiver
is amended by re-justification, never by reinterpretation. **W-004** covers one decision
record — **ADR-0007 and no other** — and **W-005** covers Phase 002's phase-level review.
Both carry compensating controls that go beyond the baseline every pull request already
meets, and both expire **2027-02-16** or as soon as a qualified second person is available.
**Neither review is independent**, in Phase 002 any more than in Phase 001.

**W-006** was added on 2026-08-17 for the same reason and on the same terms, covering a
second Phase 002 decision record — **ADR-0009 and no other**, which removes the vulnerable
`image-size` package from this documentation site. It could not be folded into W-004, which
names ADR-0007 alone, nor into W-005, because a phase-level waiver never authorises
accepting a decision record.

Two things about W-006 are stated here rather than left in the ledger. It is the **third**
explicit reviewed exception in Phase 002, which **exceeds the waiver ledger's own expected
maximum of two per phase** — an acknowledged departure, recorded as one. And it expires
**2027-02-11**, earlier than W-004 and W-005, because a new waiver for this same gap
inherits the earliest open expiry instead of restarting the clock. **The review of ADR-0009
is a structured self-review and is not independent.** Five waivers now record one problem:
this project has one person.

## Branch protection

`main` is protected. A change reaches it only through a pull request with all required
checks passing. **No account holds bypass permission, including administrators** — that is
unconditional and is not what W-001 waives.
