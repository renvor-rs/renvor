# Renvor

<Stamp />

## Renvor cannot serve a request yet

**Nothing is published.** The `renvor` crate does not exist on crates.io, so there is no way
to install it.

Phase 002 delivered a working **transport-independent kernel**: a seven-phase application
lifecycle with rollback in reverse actual initialisation order, a single-pass provider
dependency resolver under a counted work budget, layered configuration with per-key
attribution and total secret redaction, an enforced deadline on every call the kernel makes
into your code, liveness and readiness as independent answers, and a failure-injection
harness covering all 21 phase-and-behaviour combinations.

**It has no transport.** No HTTP server, no database adapter, no CLI, no way to receive a
request. You can start and stop an application; you cannot serve anything with one. That is
Phase 004's work.

**Every API is explicitly unstable** and will change once the first real transport adapter
exercises the surface and its feedback has been applied. **Do not adopt Renvor for anything
yet** — no compatibility promise applies before a `0.1.0` release.

## The command is `renvor`

The product, the facade crate, and the installed executable share one spelling: **`renvor`**.
`cargo install renvor-cli` will install a binary named `renvor`.

| Thing | Name |
| --- | --- |
| Product, framework, organization | `Renvor` |
| Facade crate | `renvor` |
| CLI crate | `renvor-cli` |
| Executable you type | **`renvor`** |
| Project state directory | `.renvor/` |
| Environment prefix | `RENVOR_` |

An earlier decision, ADR-0001, named the executable `renover` — deliberately distinct from
the product name. **ADR-0010 supersedes it**, and records the reasoning and the rejected
alternatives. Both records are in the repository.
