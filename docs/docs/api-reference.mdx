## Where the generated reference lives

The API reference is generated by `rustdoc` from the crate source, not written by hand.

- **Published:** [docs.rs/renvor](https://docs.rs/renvor) — available once the crate is
  published; the crate is not yet on the registry.
- **Locally:** `cargo doc --workspace --no-deps --open`

Verification step 5 builds it with warnings denied, so a broken intra-doc link fails the
build rather than shipping.

## What the current release exposes

`renvor` **0.0.0** provides three constants and no capability:

| Item | Type | Value |
| --- | --- | --- |
| `renvor::VERSION` | `&str` | The crate version from the manifest |
| `renvor::MSRV` | `&str` | `"1.94.0"` |
| `renvor::EXECUTABLE` | `&str` | `"renover"` |

```rust
assert_eq!(renvor::MSRV, "1.94.0");
assert_eq!(renvor::EXECUTABLE, "renover");
```

`EXECUTABLE` exists so documentation, tests, and diagnostics reference one constant rather
than repeating a string readers mistake for a misspelling. A unit test asserts it is not
`"renvor"`, which guards the naming decision against a well-meaning "spelling fix".

## Prose and API stay at the same version

This page and every prose page import the **same** version stamp partial. There is one
value, so the two cannot describe different versions of the contract (FR-056).

When the crate version or MSRV changes, `docs/_stamp.mdx` changes once and every page
follows. A release that updates the crate without updating the stamp is a defect, not a
formatting detail.
