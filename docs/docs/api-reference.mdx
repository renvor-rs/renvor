## Where the generated reference lives

The API reference is generated by `rustdoc` from the crate source, not written by hand.

- **Published:** [docs.rs/renvor](https://docs.rs/renvor) — available once the crate is
  published; the crate is not yet on the registry.
- **Locally:** `cargo doc --workspace --no-deps --open`

Verification step 5 builds it with warnings denied, so a broken intra-doc link fails the
build rather than shipping.

## What the current release exposes

`renvor` **0.0.0** is the facade over the transport-independent kernel. It re-exports
`renvor-core`, and `renvor-config` behind the default-on `config` feature.

The kernel surface covers the application lifecycle (`ApplicationBuilder`, `Application`,
`LifecyclePhase`), providers (`Provider`, `ProviderId`, `CapabilityId`, `InitContext`), errors
(`KernelError`, `ErrorCategory`), health (`HealthState`, `Liveness`, `Readiness`,
`ReadinessContributor`), cancellation, and typed state. **It exposes no transport**: nothing
here opens a socket or receives a request.

**Every one of these APIs is explicitly unstable (FR-036)** and will change once the first real
transport adapter exercises the surface. The authoritative reference is the rustdoc, which is
built with warnings denied; this page is an orientation, not a contract.

The three identity constants remain:

| Item | Type | Value |
| --- | --- | --- |
| `renvor::VERSION` | `&str` | The crate version from the manifest |
| `renvor::MSRV` | `&str` | `"1.94.0"` |
| `renvor::EXECUTABLE` | `&str` | `"renvor"` |

```rust
assert_eq!(renvor::MSRV, "1.94.0");
assert_eq!(renvor::EXECUTABLE, "renvor");
```

`EXECUTABLE` exists so documentation, tests, and diagnostics reference one constant rather
than repeating a literal. The CLI package and the binary it installs are deliberately named
differently — `cargo install renvor-cli` installs `renvor` — which is why this constant is
not simply the crate name. A unit test pins its value in both directions, so it cannot drift
silently.

## Prose and API stay at the same version

This page and every prose page import the **same** version stamp partial. There is one
value, so the two cannot describe different versions of the contract (FR-056).

When the crate version or MSRV changes, `docs/_stamp.mdx` changes once and every page
follows. A release that updates the crate without updating the stamp is a defect, not a
formatting detail.
